Text LLMs

  • The transformer doesn’t care what produced these vectors
  • The transformer processes sequences of vectors in \(\mathbb{R}^d\).
  • Everything in between is modality-agnostic.

We want to know :

  • image_to_vectors: Image → R^{N×d}
  • audio_to_vectors: Audio → R^{N×d}
  • video_to_vectors: Video → R^{N×d}

This class at High Level

Go from Text LLM to Multimodal LLM by adding three components:

  1. Encode : Turn raw modality data (pixels, audio samples, video frames) into a sequence of vectors.
  2. Align : Make vectors live in language embeddings space of the model.
  3. Fuse : Inject vectors into the LLM’s computation alongside text tokens.

From Pixels to Tokens

  • A 3D tensor: [height, width, 3] of pixel intensities (RGB).
  • Goal: produce a sequence-of-vectors representation.

Vision Transformer (ViT)

  1. Split a 224×224 image into 16 pixel × 16 pixel patches -> 14×14 = 196 patches.
  2. Flatten each patch (16·16·3 = 768 numbers).
  3. Linearly project each flattened patch to dim \(d\) (e.g., 768).
  4. Add a learned positional embedding (per-patch).
  5. Run through a standard transformer encoder stack.

Code example: ViT

CLIP

  • We have ~400M (image, caption) pairs scraped from the web.
  • We want an image encoder whose outputs are near the matching caption’s text-encoder output and far from non-matching captions.

CLIP Applications

  • Zero-shot classification: to classify an image into ImageNet classes, encode each class name with the text encoder (‘a photo of a {class}’), encode the image, pick the highest cosine similarity. No labels needed.
  • Cross-modal retrieval: the workhorse that powered the RAG module’s multimodal retrieval.

SigLIP

  • CLIP’s softmax loss requires every example to know about every other example

  • SigLIP (Zhai et al., Google, ICCV 2023) replaces softmax with a per-pair sigmoid

\[\mathcal{L}_{\text{SigLIP}} = -\sum_{i,j} \log \sigma\left(y_{ij} \cdot (t \cdot \mathbf{x}_i \cdot \mathbf{y}_j + b)\right)\]

where \(y_{ij} = +1\) for positives, \(-1\) for negatives, and \((t, b)\) are learnable.

  • Used in PaliGemma, Gemma 3, Qwen3-VL (SigLIP-2), and many others

What’s Next :

  • CLIP’s vision encoder is aligned with CLIP’s text encoder, not with Llama’s or Qwen’s text embeddings.
  • We can’t just hand CLIP vision vectors to Llama and expect it to read them.

From Understanding to Generation

Fusion : Connecting Encoder to LLM

We have:

  • A frozen text LLM (eg Llama-3-8B) that consumes token-embedding sequences in dim \(d_\text{llm}\).
  • A frozen, language-aligned vision encoder (SigLIP) that produces patch-embedding sequences in dim \(d_\text{vis}\).

How to connect them?

Can we naively concatenate them:

  1. Dimensions don’t match (\(d_\text{vis} \neq d_\text{llm}\)).
  2. Semantic spaces don’t match (SigLIP’s “language space” \(\neq\) Llama’s input-embedding space).
  3. The LLM was never trained to attend to non-text tokens.

Flamingo (DeepMind, 2022): gated cross-attention

Pros: LLM mostly frozen; supports interleaved images-and-text in long contexts (few-shot in-context multimodal prompting).

Cons: Heavy architectural modifications on the LLM, hard to extend to a new modality, lots of new parameters.

BLIP-2 : Q-Former

  • A small transformer (“Querying Transformer”) with \(k\) learnable query tokens (typically 32).

  • The Q-Former cross-attends to the ViT output and produces 32 summary vectors regardless of input image size.

  • These 32 vectors are linearly projected to LLM dim and prepended to text tokens.

  • Trains ~188M params (the Q-Former). Vision encoder (~1B ViT-g) and LLM (3–11B) frozen.

Modern Vision-Language Models

LLaVA : the MLP projector

  • A 2-layer MLP with GELU maps each vision-encoder output vector (dim ≈ 1024) to LLM embed dim (e.g., 4096).
  • Projected vision tokens are concatenated with text-token embeddings to form a single sequence.
  • Hand the joint sequence to the LLM as if it were one long text prompt.

The LLaVA training recipe (Stage 1 : Feature Alignment)

Template used by most VLMs:

  • Freeze : vision encoder (CLIP-ViT) + LLM (Viccuna)
  • Train: only the MLP projector.
  • Data: 558K image-caption pairs filtered from LAION-CC-SBU.
  • Loss: standard next-token prediction on the caption, conditioned on the image.
  • Outcome: the projector learns to map SigLIP/CLIP-space into Llama-input-space. Caption-style outputs.

The LLaVA training recipe (Stage 2 : Instruction Tuning)

  • Unfreeze: LLM (full or LoRA). Vision encoder stays frozen.
  • Train: projector + LLM.
  • Data: 150K GPT-4-generated multimodal instructions + ~515K academic VQA data.
  • Loss: same next-token prediction, but on instruction-style multi-turn conversations.
  • Outcome: the model can follow multimodal instructions, do reasoning, multi-turn dialog.

A minimal VLM

import torch, torch.nn as nn

class MiniVLM(nn.Module):
    """A LLaVA-style multimodal LLM"""

    def __init__(self, vision_encoder, llm, vis_dim, llm_dim):
        super().__init__()
        self.vision = vision_encoder            # SigLIP, frozen
        self.proj   = nn.Sequential(            # the MLP projector
            nn.Linear(vis_dim, llm_dim),
            nn.GELU(),
            nn.Linear(llm_dim, llm_dim),
        )
        self.llm = llm                          # Llama-style decoder

    def forward(self, pixel_values, input_ids, image_token_id):
        # 1. Encode the image
        vis = self.vision(pixel_values).last_hidden_state  # [B, N_patches, vis_dim]
        vis = self.proj(vis)                                # [B, N_patches, llm_dim]

        # 2. Get text embeddings
        txt = self.llm.embed_tokens(input_ids)              # [B, N_text, llm_dim]

        # 3. Splice vis vectors in where the <image> placeholder sits
        x = splice_image_at_placeholder(txt, vis, input_ids, image_token_id)

        # 4. Standard LLM forward pass on the joint sequence
        return self.llm(inputs_embeds=x)

State of the Art in VLMs (2025-26)

Qwen3-VL

Qwen3-VL

Architecture

  • Vision encoder: SigLIP-2 (continues training with dynamic input resolutions).
  • DeepStack: multi-level ViT features fed to projector.
  • Enhanced interleaved-MRoPE.
  • Native 256K context (extensible to ~1M).
  • Dense variants: 2B / 4B / 8B / 32B. MoE variants: 30B-A3B, 235B-A22B.

Qwen3-VL

Capabilities (training-data choices)

  • OCR & dense text: multilingual OCR training data. Benefits from dynamic resolution.
  • Grounding: outputs bounding boxes as text tokens, e.g., <|box_start|>(x1,y1),(x2,y2)<|box_end|>. This is a vocabulary + training data choice, not an architecture change
  • Agentic browsing: trained on GUI screenshots paired with click actions
  • Thinking mode: chain-of-thought before answer, gated by a flag

Performance (Nov 2025 benchmarks)

  • MMMU: 78.7% (Qwen3-VL-235B); GPT-5 was at 82.7% at the time.
  • MathVista: 84.9–85.8% — beats Gemini 2.5 Pro (84.6%) and GPT-5 (82.7%).
  • DocVQA: 96.5%.

Gemma 3 (Google, 2025)

  • Vision encoder: frozen SigLIP-400M at fixed 896×896.
  • 256 visual tokens per image (fixed, regardless of input).
  • Pan-and-Scan (P&S): for non-square or high-resolution images, an adaptive windowing algorithm segments the image into equal-size crops, resizes each to 896×896, and encodes each independently.
  • 128K context (vs. Qwen3-VL’s 256K).
  • Local-global attention pattern (5 local : 1 global)

Audio Representation

  • A 1D waveform: amplitude vs. time, typically sampled at 16 kHz for speech.
  • 30 seconds of audio = 480,000 samples. Far too long to feed directly.

Preprocessing: log-mel spectrogram

  • Slide a 25 ms window over the waveform with a 10 ms stride.

  • For each window, compute the power spectrum, then apply 80 mel filterbanks (perceptually-spaced frequency bins).

  • Take the log.

  • Result: a 2D matrix of shape [80 mel bins, ~3000 time frames] per 30-second clip.

A spectrogram looks like an image: width is time, height is frequency, intensity is energy. The same encoder ideas that worked for ViT should work here

Whisper (OpenAI, 2022)

ViT for audio

Whisper Architecture

  1. Input: log-mel spectrogram of shape [80, 3000] (30 seconds @ 16 kHz).

  2. Stem: two Conv1d layers over the time axis (kernel=3, stride=2 on the second). This is the audio analog of ViT’s patchify. Halves the time dimension.

  3. Output of stem: [1500, d] - a sequence of 1500 audio “patches” (each = 20 ms of audio).

  4. Encoder: standard transformer with sinusoidal positional embeddings.

  5. Decoder (Whisper-specific): transformer decoder that cross-attends to encoder output and produces text tokens (BPE, same as GPT-2). Predicts language ID + transcription + timestamps via special tokens.

Qwen2-Audio

  • Architecture: Whisper-style encoder + Qwen LLM + MLP projector. Exactly the LLaVA recipe, with Whisper in place of CLIP/SigLIP

  • Training: same two-stage recipe (align projector -> instruction tune).

Audio Generation

Task : How to autoregressively generate a waveform?

Solution : discrete audio codec tokens

  • A neural audio codec (e.g., EnCodec, SoundStream) compresses raw audio into a small sequence of discrete tokens (~50-75 tokens/second) using a learned VQ-VAE-style tokenizer.

  • A neural vocoder reverses the process: discrete tokens -> waveform.

  • Once audio is discrete, an autoregressive LLM can generate it just like text.

Qwen3-Omni : SotA in 2025-26

  • Inputs: text, image, video, audio -> each encoded by its respective tower, projected, and concatenated. Same fusion pattern as everything we’ve seen.

  • Audio encoder: Qwen3-Omni replaced Whisper with AuT (Audio Transformer) -> trained from scratch on 20 million hours of supervised audio

  • Two sub-models on the output side, both MoE:

    • Thinker (MoE): the main LLM. Autoregresses over text tokens.
    • Talker (MoE): smaller streaming model that produces discrete audio codec tokens in real time -> vocoder -> speech.

Talker conditions only on audio and visual multimodal features -> not on Thinker’s text representations. Allows post processing of text output (e.g., add prosody, emotion) before generating speech.

Multimodal Inference Engineering

  • Token explosion & prefill dominance

For text LLM chat: - Prompt is usually short (100s–1000s of tokens). Decode dominates wallclock. - TTFT (time-to-first-token) is small relative to total response time.

For multimodal: A 7B VLM

  • Input : single 2048×1536 image, 50-token query

  • Vision tokens: ~1500. Total prefill tokens: ~1550.

  • Input : 4K page (e.g., a document) + 50 token query

  • Vision tokens: 10,000+. Total prefill tokens: 10,050+

  • Prefill becomes the bottleneck.

Quantizing Multimodal LLMs

  • Vision/audio towers: keep at BF16/FP16. They’re small relative to the LLM, and quantization hurts perception quality disproportionately (especially OCR and fine details).
  • LLM body: GPTQ / AWQ / FP8 / INT8 / INT4 normally
  • Projector: stays at full precision (tiny, no benefit to quantize).
